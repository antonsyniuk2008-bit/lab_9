# Звіт з лабораторної роботи №9
**Тема:** Сторінка логіну (Сесії). Створення простого екрану входу з використанням “захардкоженого” логіну/пароля та запис статусу в \$_SESSION.
**Мета:** Зрозуміти проблему зберігання стану (stateless) в протоколі HTTP та навчитись ідентифікувати користувача між перезавантаженням різних сторінок на основі Cookie і Сесій.
**Стек технологій:** PHP Sessions (session_start(), \$_SESSION), HTML, CSS, Apache.

---

## 1. Фрагменти коду

### Код авторизації (`login.php`)
<?php
session_start();
$userEmail = 'antonsyniuk2008@gmail.com';

$userPassword = hash('sha256', '123'); 


if (isset($_POST['email']) && 
    isset($_POST['password']) && 
    $_POST['email'] === $userEmail && 
    hash('sha256', $_POST['password']) === $userPassword) {
    $_SESSION['is_logged'] = true;
    $_SESSION['uid'] = 99; 
    $expireDate = time() + 20; 
    setcookie('user_time', time(), $expireDate, '/');
    header('Location: cabinet.php');
    // Після header('Location: ...')
    exit;

} else {
    $errorMessage = "Невірно введений email або пароль!";
}
?>
<!DOCTYPE html>
<html lang="uk">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Помилка входу</title>
    <link rel="stylesheet" href="style.css">
</head>
<body>
    <?php 
    include 'navigation.php'; 
    ?>
    
    <h1>Помилка авторизації</h1>

## 4. Відповіді на контрольні запитання



1. Що таке "stateless" (HTTP без стану) і чому сервер нас не впізнає?

• По-простому: Це означає, що у сервера пам'ять як у золотої рибки. Ти клацнув на сторінку — сервер її показав і одразу забув, хто ти такий.
• Чому не впізнає: Коли ти переходиш на іншу сторінку, для сервера це абсолютно новий запит від абсолютно невідомого чувака. Без сесій він ніяк не згадає, що секунду тому ти вже вводив правильний пароль.

2. Яка різниця між Cookie та Сесією? Де вони лежать?

• Cookie (куки) зберігаються в браузері (на твоєму комп'ютері). Це звичайний текст. Користувач може залізти в налаштування і вручну їх змінити. Тому туди не можна ховати паролі — зламають за секунду.
• Сесії ($_SESSION) зберігаються на сервері. Користувач не може туди дотягнутися чи щось там підробити. Тому статус «я залогінився» ми пишемо тільки в сесію.

3. Що таке PHPSESSID і навіщо він потрібен?

• По-простому: Це номерок у гардеробі. Коли ти заходиш на сайт, сервер створює на своєму диску файл із твоїми даними (наприклад, що ти адмін), а тобі в браузер дає лише маленьку куку з унікальним номером — PHPSESSID.
• Коли ти ходиш по сайту, твій браузер щоразу показує серверу цей номерок. Сервер дивиться: «Ага, номерок №123, шукаю у себе цей файл... О, це адмін, пускаю!».

4. Навіщо session_start() писати на самому початку і що за помилка "Headers already sent"?

• Навіщо на початку: Сесія передає той самий кук-номерок через службові заголовки (Headers). За правилами інтернету, сервер спочатку повинен виплюнути всі приховані заголовки, а вже потім вантажити сам HTML-код сайту.
• Що за помилка: Якщо ти виведеш хоча б один тег <html> або навіть поставиш випадковий пробіл перед <?php, заголовки закриються і відправляться. Якщо після цього викликати session_start(), вискочить помилка «Headers already sent» (заголовки вже пішли), і сесія просто зламається.

5. Що робить header('Location: ...') і навіщо після нього писати exit?

• Що робить: Це звичайний редирект (перенаправлення). Команда для браузера: «Тобі сюди не можна, швидко лети на сторінку login.php».
• Навіщо exit: Ця команда дає наказ браузеру, але сам сервер продовжує читати і виконувати PHP-код далі по файлу! Якщо не написати exit;, сервер виконає весь секретний шматок коду під редиректом і віддасть його в мережу. Звичайний юзер цього не помітить, бо його перекине браузер, але хакер через спеціальні програми зможе прочитати все, що ти намагався сховати. exit просто вирубає скрипт намертво.
